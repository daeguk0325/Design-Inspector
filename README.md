# Design Inspector Tool

로컬 웹 UI를 실제 브라우저에서 실시간으로 검사하고, 선택한 컴포넌트를 로컬 Ollama와 함께 UI/UX 개선 방향을 토론하며, 임시 CSS를 즉시 적용·되돌리는 워크스페이스입니다.

## 핵심 기능

- 별도 타깃 수정 없이 격리 loopback proxy를 통해 로컬 웹 앱 실행
- Freeze 후 DOM 요소 선택, 번호 오버레이, 논리 anchor와 `file:line` citation
- 선택 요소의 **측정된 스타일 사실**을 프롬프트에 함께 전송 (§9e)
  - 색상 10 / 타이포 11 / 박스 19 / 레이아웃 12 / 모션 4 = longhand 56개 속성
  - 기본값은 프로퍼티별로 제거되므로 이상한 값만 남는다 (`display:block`, `rgba(0,0,0,0)` 등)
  - `oklch()`, `color(srgb …)` 같은 현대 색상 문법은 1×1 캔버스를 거쳐 `#rrggbb`로 변환된다. 변환 불가 값은 원문 통과 없이 **버려진다**
  - **파생 측정값**도 같이 갑니다 — 모델에게 계산시키지 않고 브리지에서 한 번만 계산합니다
    - `contrast 4.54:1 min 4.5 pass` — WCAG 2.x 판정. 비율은 소수 둘째 자리에서 끊고 판정도 그 값에서 내려서, 출력된 숫자와 판정이 어긋날 수 없습니다
    - 배경을 단색으로 잴 수 없으면 `contrast unmeasurable`로 명시합니다. 못 잰 것을 못 잰 대로 말하는 편이 임의의 숫자를 만들어내는 것보다 낫습니다
    - `text-truncated` — 1px를 넘게 넘칠 때만 붙습니다. 안 잘리면 키가 아예 없습니다
    - `font-load fallback` — 문서가 선언한 폰트가 실제로는 로드되지 않은 경우
  - 선택 요소 두 개 이상이 서로 겹치면 `Measured relations` 줄이 추가됩니다
    - 교집합 박스와 겹치는 비율만 말합니다. **누가 위에 있는지는 측정하지 않았고**, 그 사실도 줄에 그대로 적힙니다
  - 상세 보기 팝업에서는 스타일 그룹 앞에 `Measured` 그룹이 붙고, 대비를 잰 **배경색 스와치**가 함께 보입니다. 측정 불가한 대비는 "not measurable"로 표시됩니다
  - 프롬프트에서 `untrusted-evidence` 펜스로 감싸고, 이미지가 없더라도 항상 전송된다
  - 이미지와 수치가 충돌하면 수치를 따르도록 시스템 프롬프트에 명시
    - 이미지에는 판단(구도, 균형, 주변과의 관계, 어디에 시선이 가는지)을, 수치에는 측정만 맡깁니다. 스크린샷에는 크기 기준이 없으므로 수치를 읽어내는 것은 금지
  - 이미지 미전송 시 프롬프트에 "이 요청에는 이미지가 첨부되지 않았습니다"를 한 줄 명시 — 모델이 근거 없이 시각을 지어내는 대신 정직하게 밝힌다
- 입력창 안에서 태그와 문장을 자유롭게 섞어 쓰기
  - 썸네일, 요소명, 상세 보기, `×` 즉시 삭제
  - 태그는 **커서 위치에** 삽입되므로 `make ({1}) and ({2}) more compact` 처럼 문장 한가운데 놓입니다
  - Backspace 두 번으로 실수 방지 삭제 (삭제하면 대상 페이지의 선택도 함께 해제)
    - 길게 누르고 있으면 arm이 풀려서 뒤쪽 글자가 계속 지워집니다
    - 드래그로 태그를 걸쳐 선택하면 두 번째 확인 없이 바로 삭제됩니다
  - `Ctrl+Z` 로 태그와 대상 페이지 하이라이트가 함께 되살아납니다
  - 삭제 시 대상이 선택을 유지하면 태그가 복구되고 안내 문구가 표시됩니다
- 인용 기호 `({1})` 은 어떤 언어·템플릿 문법에도 속하지 않아 파싱이 모호하지 않습니다
  - 전송 문장, 인용 목록, 이미지 매핑, 모델 시스템 프롬프트가 모두 같은 표기를 씁니다
  - 전송된 내 말은 사용자 채팅에서 `({1})` 자리가 실제 컴포넌트 칩으로 다시 렌더링됩니다
  - 모델이 쓴 전달문에 있는 `({1})` 도 클릭 가능한 칩이 되고, 누르면 대상 페이지에서 그 컴포넌트를 다시 선택해줍니다
  - 코드 블록·인라인 코드·수식 안의 표기는 그대로 보존되고, 해당 컴포넌트가 없는 번호는 칩으로 바뀌지 않고 텍스트로 남습니다
- 자연스러운 모션
  - 태그 등장·퇴장,armed 펄스, 캡처 스켈레톤, Send 시 태그→채팅 전환
  - `prefers-reduced-motion`을 존중해 모션이 필요한 만큼만 축약됩니다
- 선택 컴포넌트 자동 crop과 Contact Sheet를 로컬 Vision Ollama로 전송
- 단일 UI/UX 디자이너·개발자 역할. 고정 섹션 템플릿 없음 — 요청에 맞는 답변만
  - `## 디자이너 전달문`은 **명시적으로 요청할 때만** 생성
- Freeze는 실제 정지 상태 — hover, 클릭, 드래그, 키보드, 포커스, 입력, CSS 애니메이션이
  전부 멈춥니다. 스크롤은 유지되어 화면 밖 컴포넌트를 볼 수 있습니다
- 검증된 CSS proposal을 iframe DOM에 자동 runtime preview
  - 프로젝트 소스 파일은 변경하지 않음
  - 요소 사이 간격(`gap`)까지 반영
  - 응답별 transaction Undo와 전체 Reset
  - 세션·route·reload 후 논리 anchor 재바인딩
- **제안(Proposal) 상태 기계** — 적용된 preview는 사용자가 결정하기 전까지 잠정입니다
  - `Accept` — 적용 유지 + 다음 요청에 간결한 수정 내역으로 기록
  - `Reject` — 되돌린 뒤 `reverted`로 기록
  - 결정하지 않고 다음 채팅을 보내면 자동 `Reject`
  - 메시지마다 어떤 변경을 결정하는지와 그 상태를 표시
- `변경 내역` 패널 — 승인된 변경이 실측 before → after 값으로 누적
- `제안서 복사` — 누적 내역을 실행 가능한 격식 문서로 생성 (결정론적, 모델 미사용)
  - 대상이 `data-inspector-file`을 심었다면, 각 컴포넌트에 `참고 위치`와 인용된 줄을 중심으로 최대 40줄을 붙입니다
- 인용된 `file:line`이 있으면 실제 소스 텍스트를 읽습니다 (§9h)
  - 상세 보기 팝업의 `Source` 블록(줄 번호 표시)과 `제안서 복사` 문서의 `참고 위치`, 두 곳에만 쓰입니다
  - Vite 개발 서버는 `/src/...`에 대해 변환된 모듈을 돌려주고 프록시는 CORS 헤더를 주지 않으므로, 프로젝트 루트를 이미 아는 Supervisor가 읽습니다
  - `data-inspector-file`이 없는 대상은 아무 요청도 나가지 않습니다. 조회가 실패해도 팝업은 조용합니다 — 위치 줄이 이미 unavailable을 말하고 있습니다
- `Revert`(사용자 메시지, 아이콘) — 그 지점 이후 대화 삭제 + preview 해제 + 원본 텍스트 복원,
  실행 후 채팅창 위에 `Undo rewind` 버튼 표시
- Desktop / Tablet / Mobile viewport 프리셋
- 동일 target 세션 간 selection, capture, preview 완전 격리

## 실행

```bash
npm install
npm run dev
```

`npm run dev`는 App A, Supervisor, Launcher를 시작합니다. 대상 프로젝트는 Launcher에서 선택합니다.

```bash
npm run dev:web   # 저장된 대상과 App A만 실행
npm test
npm run typecheck
npm run lint
npm run build
```

## 사용 흐름

1. Launcher에서 로컬 프로젝트를 실행합니다.
2. `Ctrl/Cmd+Shift+F` 또는 Freeze 버튼으로 검사 모드를 켭니다.
3. 대상 화면에서 컴포넌트를 선택합니다.
4. 입력창 상단의 태그를 확인하고 개선안을 요청합니다.
5. Ollama의 한국어 답변과 선택 스타일을 확인합니다.
6. 각 답변의 `Accept` 또는 `Reject`로 결정합니다.
   - `Accept` — 그대로 쌓이고 다음 요청에 이어집니다
   - `Reject` — 그 수정만 되돌립니다
   - 아무것도 누르지 않고 다음 채팅을 보내면 대기 중인 제안은 자동으로 되돌려집니다
7. Header의 `변경 내역`에서 누적된 수정과 `제안서 복사`를 확인합니다.
8. 이전으로 되돌리려면 사용자 메시지의 Revert 아이콘을 누릅니다. 되돌린 내용은
   채팅창 위 `Undo rewind`에서 복구할 수 있습니다.

## 안전 경계

- 검사 대상 프로젝트 파일은 읽기만 하며 CSS preview도 런타임 DOM에만 적용됩니다.
  인용된 소스 조각도 읽기만 하고, 대상 프로젝트에 쓰는 경로는 없습니다.
- 소스를 읽더라도 **모델에게는 보내지 않습니다.** 인용한 `path:line` 주변 텍스트는
  상세 보기 팝업과 `제안서 복사` 문서에서만 쓰이고 프롬프트에는 들어가지 않습니다.
  모델 전송에 들어가는 것은 대상 페이지에서 온 텍스트(스타일 값, 라벨, 요소 텍스트)뿐입니다.
- 소스 조회는 프로젝트 루트 밖으로 나갈 수 없습니다. 상대 경로·정방향 슬래시만 허용하고
  `..`·드라이브 문자·UNC·선행 슬래시를 거부하며, 경로 길이와 지원 확장자를 제한합니다.
  `node_modules`와 `.git`는 **어느 깊이에서든** 거부되고, 심볼릭 링크를 해석한 뒤에
  경계 이탈을 다시 확인합니다. 최대 512KB, 창은 400줄까지이며 인용된 줄을 항상 포함합니다.
- 이미지 crop과 preview 이미지 바이트는 localStorage에 저장하지 않습니다.
- **엔드포인트는 loopback Ollama로만 제한됩니다.** 다만 Ollama의 `:cloud` 모델은
  loopback 엔드포인트에서도 Ollama 클라우드를 경유하므로, 이 경우 이미지와 측정된
  스타일 값이 기계를 떠납니다. 전송은 계속되고 (§9e) 프롬프트와 컴포저에 그 사실이
  명시됩니다 — 차단이 아니라 고지입니다.
- **스타일 값은 이미지 전송 여부와 무관하게 매 전송마다 전송됩니다.** 선택 요소의
  측정값과 요소 텍스트가 모델이 그림을 볼 수 없더라도 프롬프트에 들어갑니다.
  브리지에서 1×1 캔버스로 sRGB 정규화(변환 불가 값은 원문 통과 없이 제거), wire에서
  부분집합 allowlist 검증, 상태 저장 직전에 재검증, 프롬프트에서
  `untrusted-evidence` 펜스로 감싸고 untrusted 규칙에 명시합니다. 엔드포인트가
  loopback면 이 자체는 우려가 아니지만, 원격 모델을 구성하기 전에 함께 재검토할
  항목입니다.
- 측정된 스타일 값은 모델 전송에만 포함되며, 사람이 다른 도구에 붙여넣는
  "Copy agent prompt" 출력에는 들어가지 않습니다.
- model이 생성한 selector나 임의 CSS는 허용하지 않고 visual-only allowlist만 검증합니다.
- 실제 소스 수정은 별도 diff 승인·백업·undo 단계로 제공하지 않습니다.
